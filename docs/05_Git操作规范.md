# Git 操作规范

## 1. 操作前确认

必须确认：
- 仓库名称；
- 目标分支；
- 当前任务允许修改的范围；
- 哪些仓库只是参考，禁止修改。

## 2. 修改原则

1. 参考仓库只能读取时，不得写入。
2. 不把其他项目文件误提交到目标仓库。
3. 不提交临时文件、缓存、生成物或调试文件，除非项目明确要求。
4. 不为了整理历史而擅自执行 rebase、reset、force push 等破坏性操作。

## 3. 提交前检查

至少检查：
- 实际变更文件列表；
- 是否存在无关修改；
- 是否遗漏应该提交的文件；
- 文件内容是否与用户要求一致；
- 是否存在明显路径、命名或格式错误。

重要任务或用户明确要求时，应进行多轮检查。

## 4. 提交信息

提交信息应说明本次修改目的，例如：

`docs: add global agent engineering standards`

`fix: correct protocol frame parsing`

`refactor: isolate transport from protocol layer`

禁止使用没有信息量的提交信息，如：
`update`
`modify`
`test`

## 5. 提交后

应确认：
- 提交成功；
- 提交位于正确分支；
- 提交包含预期文件；
- 没有误改参考仓库或其他工程。
