# 技术分析规范

## 1. 必须结合实际案例

技术分析不能只讲抽象公式或概念。

应尽量使用真实工程变量、信号、频率、时间点、输入输出、路径或器件作为案例，再解释一般规律。

## 2. 公式统一格式

凡涉及公式、定理、变换性质、近似式、判据或数值计算，按以下顺序：

1. 给出一般公式；
2. 定义每个变量；
3. 标明单位；
4. 给出必要推导；
5. 单独进行“代入实际数值”；
6. 给出结果；
7. 解释工程意义。

禁止直接从“带具体数字的公式”开始。

## 3. 推导要求

用户要求理解原理时，不只给最终结论。

推导应说明：
- 从什么已知关系开始；
- 每一步为什么成立；
- 使用了什么假设；
- 哪一步是近似；
- 近似在哪些条件下有效。

## 4. 时间与频率问题

分析采样、控制、滤波、PWM、通信、延迟时，应明确：
- 时间基准；
- 采样时刻；
- 数据可用时刻；
- 计算完成时刻；
- 输出或比较值真正生效时刻；
- 一个周期还是下一个周期生效。

分析频率时，应明确“这个频率属于什么”：
- 信号频率；
- PWM 频率；
- 采样频率；
- 控制环更新频率；
- 电气频率；
- 机械频率；
- 通信刷新频率。

不能把这些频率混为一谈。

## 5. 电流、电压、EMC、接地分析

需要分析电流路径时，必须形成完整闭合回路。

根据问题需要分别说明：

### 导电电流
电子通过导体、器件导电通道实际移动形成的电流。

### 位移电流
由变化电场和电容耦合产生的等效电流。

必须明确：
电子不会直接穿过电容绝缘介质，只在导线和电容两侧极板上重新分布或移动。

### 电子运动路径
当用户要求“电子实际怎么走”时，应区别于传统电流方向单独说明。

## 6. 控制系统分析

涉及带宽、延迟、相位、采样和控制周期时：
- 必须说明延迟由哪一部分引入；
- 必须区分计算延迟、采样延迟、滤波延迟、PWM 更新延迟和通信延迟；
- 必须明确哪一部分是真正瓶颈；
- 不应把不同来源的延迟简单相加而不说明前提。

## 7. 比较类问题

比较方案时：
- 使用相同输入条件；
- 使用相同指标；
- 明确假设；
- 分别说明共同部分和真正有差异的部分；
- 优先指出决定性能差异的瓶颈，而不是堆参数。
