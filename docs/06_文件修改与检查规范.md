# 文件修改与检查规范

## 1. 通用原则

无论修改代码、Markdown、配置、CSV、Excel、脚本还是其他工程文件，都遵守：

1. 只修改任务要求范围；
2. 保留未要求修改的有效内容；
3. 不擅自改变格式和结构；
4. 修改后检查前后一致性；
5. 不把临时产物提交到正式目录。

## 2. Markdown

检查：
- 标题层级；
- 代码块是否闭合；
- 表格是否完整；
- 文件路径是否准确；
- 术语和命名是否统一；
- 是否存在重复内容。

## 3. 配置与代码文件

检查：
- 语法；
- 编码；
- 路径；
- 依赖；
- 键名；
- 数据类型；
- 默认值；
- 与其他配置项的关联。

## 4. 表格类文件

修改表格时：
- 不破坏已有公式；
- 不破坏单元格引用；
- 不擅自删除其他列；
- 保持同列数据类型一致；
- 修改后检查表头、单位、型号、备注及关联字段。

## 5. 生成文件与源文件

应区分：
- 正式源文件；
- 自动生成文件；
- 中间文件；
- 检查文件；
- 临时文件。

除非用户明确要求，不能把检查产物或中间文件当成正式交付物提交。

## 6. 多轮检查

用户要求“检查多次”时，不能只重复一句“已检查”。

每轮应关注不同维度，例如：
1. 内容正确性；
2. 结构与一致性；
3. 变更范围与提交完整性。

发现问题后应先修改，再重新检查。
