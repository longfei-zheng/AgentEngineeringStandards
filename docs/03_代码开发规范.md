# 代码开发规范

## 1. 修改前

在修改代码前应先确认：
- 当前架构；
- 模块职责；
- 主要接口；
- 调用关系；
- 数据流；
- 线程或异步关系；
- 与目标修改直接相关的现有实现。

不能在不了解现有代码的情况下直接重写。

## 2. 修改范围

1. 只修改任务要求范围。
2. 不做无关重构。
3. 不擅自修改公共接口。
4. 不擅自修改目录结构、命名规则、数据格式或协议。
5. 不删除看似无用但尚未确认用途的代码。
6. 必须修改多个模块时，说明依赖关系并保持接口一致。

## 3. 分层与模块边界

已有项目存在明确分层时：
- 不允许越层调用；
- 不允许为图方便把底层细节泄漏到上层；
- 数据所有权和转换职责应放在正确层；
- UI、业务、协议、驱动、存储等职责不得随意混用。

## 4. 异步与实时逻辑

涉及线程、串口、网络、中断、DMA、PWM、实时采样等逻辑时：
- 明确谁发起；
- 明确谁拥有数据；
- 明确什么时候数据有效；
- 明确回调、信号或中断的执行上下文；
- 避免阻塞不应阻塞的线程；
- 避免隐藏竞态条件。

## 5. 修改后

至少检查：
- 是否能编译或通过静态检查；
- 接口是否一致；
- 变量和类型是否匹配；
- 错误路径是否处理；
- 是否破坏原行为；
- 是否引入未使用代码；
- 是否误改无关文件。

若无法实际运行测试，应明确说明未验证的部分，不能宣称已经通过运行验证。
