# 文档编写规范

## 1. 目标

文档应让读者能快速找到答案，并理解问题、原因、方案和结果。

## 2. 章节组织

原则：
- 一个章节负责一个主题；
- 同一知识点集中说明；
- 避免同样内容散落在多个章节；
- 章节层级尽量浅；
- 不为了形式增加没有内容的章节。

## 3. 闭环

技术文档应尽量形成：

问题 → 原因 → 原理 → 方案 → 验证 → 结论

如果是代码调用链，应形成：

入口 → 实际对象 → 实际函数 → 数据变化 → 最终目标

## 4. 标识必须具体

代码分析中，用户需要知道具体调用对象时，不只写抽象成员名。

应尽量给出完整限定关系，例如：
`结构体类型::结构体数组[实际下标].成员::实际函数`

目的不是追求语法形式，而是让读者快速知道“本次实际调用的是谁”。

## 5. 路径、文件名和变量名

1. 原样保留用户指定名称。
2. 不擅自缩写。
3. 不随意改大小写。
4. 路径必须准确。
5. 文档中的代码和实际工程应一致。

## 6. 去重

修改文档时，应优先：
- 合并重复内容；
- 删除前后矛盾；
- 把分散解释集中到最合理的位置；
- 保留原有仍然有效的信息。

不要通过不断追加新段落制造冗余。
